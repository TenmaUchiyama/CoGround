全体構成

Quest（Unity）が場面と人の位置を送り、グラウンディングサーバーがルールの判定と計画を持ち、ROS 上の Fetch が動きます。サーバーとは WebSocket（/ws）の要求・応答と、全体状態の配信（state.updated）で話します。

3 / 7

ルールの設計

1 つのルールを Institutional Grammar の形に分けて持ちます。計画（予測した状態列 τπ）と実行（観測した状態列 τobs）で、同じ関数 evaluate() を使って判定します。分からない事実は「不明」として扱い、勝手に補いません。

R = (N, S, T, W, φ) → Verdict ∈ {violated, compliant, not_applicable, undetermined}
flowchart LR
  N["N 規範 norm ／ prohibition / obligation / permission"] --> E
  S["S Scope ／ from・until（家の時計） ／ requester・when（状態の条件）"] --> E
  T["T 対象 target ／ object / zone / robot ／ id か where 属性 = 値"] --> E
  W["W 評価区間 window ／ at_contact / during_base_motion ／ at_place_complete / whole"] --> E
  P["φ 述語 predicate ／ contact · placed_in ／ footprint_overlaps · near_child ／ base_stopped（＋transition）"] --> E
  X["exception_of（許可） ／ 元の禁止の適用範囲を狭める"] --> E
  TRACE["状態列 WorldSample[] ／ 予測 τπ か 観測 τobs"] --> E{{"evaluate()"}}
  E --> V1["violated ／ 違反の証拠あり"]
  E --> V2["undetermined ／ 足りない事実 missing を返す"]
  E --> V3["compliant"]
  E --> V4["not_applicable"]

三値の論理

述語は True / False / 不明 を返し、and3 / or3 / not3 で組み合わせます。子供かどうか分からない人が近くにいれば、R4 は「不明」になり、安全側で止めます。

例外（許可）

「私が頼んだときは触ってよい」は permission の exception_of: R1 で登録します。依頼者が分からなければ例外の成立も不明になり、結論は未確定です。

候補の絞り込み

スキルが変える項目（SKILL_CHANGES）とルールが読む項目（depends_on）が重なるルールだけを評価し直します。訂正のときも同じ表で影響を受けるルールを探します。

画像から場面へ（データの流れ）

カメラ画像は Quest の上で JPEG にして検出コンテナへ送り、返ってきた矩形を Quest 側で 3D の箱にします。いまは検出結果を表示（デバッグの箱・DR マスク）に使っていて、場面としてサーバーへ送る部分と VLM による属性推定はまだありません。

属性の根拠

Attribute.source は ground_truth / detector / vlm / user。値が無ければ「不明」で、ルールの判定は undetermined と足りない事実（例: plate_A の 属性 fragile）を返します。

訂正は上書きで持つ

住人の訂正は届いた観測とは別に保存し、次の scene.update のあとも効きます。訂正すると関係するルールだけを評価し直し、変わった行を correction.changes で返します。

実行と監視（R2・R4）

実行中は Monitor が人の位置・台車の位置・時刻を見張り、R4 の条件が成り立つ（または不明になる）と台車を止めます（hold）。条件が解けても、残りの経路を判定し直すまでは止めたままです。

  autonumber
  participant P as Quest（人の位置）
  participant M as Monitor
  participant X as Executor
  participant R as ROS（pick_place_server）
  X->>R: skill/goal navigate（keepout_zones 付き）
  loop 0.2 s ごと
    P->>M: people.update {people[]}
    M->>M: R4 を観測で判定
  end
  Note over M: 子供が 5 m 以内 / 人の観測が 2 s 途切れた
  M->>R: skill/hold {hold: true, reason}
  M->>M: holds に「止めるよう求めた時刻・距離」を記録
  R-->>M: 台車の速さ → 「実際に止まった時刻」を記録
  Note over M: 条件が解ける
  M->>R: nav/route_request（残りの経路を R2 で判定し直す）
  R-->>M: route_result
  alt 経路が使える
    M->>R: skill/hold {hold: false}
  else 使えない
    M->>X: route_blocks に入れ、その物は deferred

型

サーバーは pydantic v2（models.py, norms/model.py, norms/task.py）、Unity は Newtonsoft の DTO（CoGroundSceneTypes.cs, CoGroundPlanTypes.cs）。座標はどちらも Unity のワールド座標（左手系、Y が上）で、ROS に渡すときに (x, y, z) → (z, −x, y) に直します。
