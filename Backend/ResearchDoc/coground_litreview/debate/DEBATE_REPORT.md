## 1. 結論

**5者全員が同じ枠組みに投票した: 「状態（After）か過程（再生）か」を比べる実証論文。システムは実験装置、設計空間は議論の節に置く。**

- システムとしての新規性は弱い。どの構成要素にも2024〜2026年の先行例がある。
- 防御できる新規性は、まだ誰も行っていない実験にある: **表示の種類（状態 / 過程）× 欠陥の種類** が、目標達成の判断に与える効果。
- 「AR対2D」は主張の中心に置かない。先行研究の結果が割れており、4件目の「差なし」になるおそれがある。副次的な要因か続編にする。

論文の差分を1文で言うと（査読者の最終版）:

> 実行前プレビューはロボットの計画を過程として見せてきたが、誤った最終状態の検出を助けていない。本研究は、ロボットが予測したAfter状態を現在のシーンと並べて見せると、委譲した依頼がどこまで達成されるかの判断が改善するか、どの種類の誤りで助けになり、どの種類で問題を隠すか（特に欠落）、依頼に結び付けた印が何を変えるかを検証する。

## 3. 議論で新しく分かったこと

### 3.1 MARCERが最も強い主張を狭めた
懐疑派が第2ラウンドでMARCER（HRI 2025）の本文を確認した（PDFのキーワード検索と前後の精読）。

- 図2(d)の説明に、承認後に「関連する物体の現在・将来・最終状態を示すARデジタルツインと、ロボット動作のシミュレーション」でプレビューできるとある。計画は音声からLLMが生成する。つまり、**ロボットが予測した物体の最終状態を、実行前にその場で見せる**例がすでにある。
- ただし、表示はルールごと・関連物体ごとで、動作の再生と一緒に出る。静止したシーン全体のBefore/After、不一致の印、原因表示はない。
- 評価はN=15、比較条件なし、課題完了とSUS（70.83）のみ。判断の正確性は測っていない。
- 未確認: 最終状態がどう描画されるか（静止ツインか、再生の終端か）は図を見ていないので不明。

残る差分は「静止・シーン全体・並置・既定の表示」に、不一致の印と原因リンクを加えたものに狭まる。

### 3.2 欠落の問題（理論派）
達成されなかった部分目標は「動かなかった物体」であり、Before/Afterの差分に現れない。CoGroundが最も見せたい失敗を、差分表示は最も苦手とする。全員がこの指摘を認めた。

解決の方向（3者の案が収束）:
- 表示を3層に分ける: (a) 変化の差分、(b) スコープ（ロボットが依頼の対象と解釈した物体）、(c) 判定（未達成）。
- (b)は中立の印として常に見せる。欠落は「印があるのに変化しない物体」として見える。結び付けの誤りは、解釈の誤りとして現れる。
- (c)の判定を見せると、ユーザーは判断せずに読むだけになる。これは検出のテストではなく、プランナーの判定への依存のテストとして別条件で扱う。

### 3.3 欠陥を「プランナーが知っているか」で分ける
- **プランナーが把握している不足**（ルールによる阻止、実行不可能）: システムが伝えればよい。ユーザーの仕事は受け入れるかどうかの判断と修正。
- **プランナーが把握していない不足**（計画はロボットの解釈を満たすが、ユーザーの意図を満たさない）: 人間の判断が必要な唯一の領域。検出力（d′）はここで測る。

### 3.4 依頼の解釈の誤りは実装上起こりうる
懐疑派は「ルールベースのプランナーでは解釈の誤りが起きない」と指摘したが、理論派と査読者が `grounding_server/README.md` を読んで訂正した。LLMが言語をルール・規範・対象物体に変換しており（`rules.compile`、`norms.compile`、`task.request` の `interpret: true`）、プランナーは決定的でも入力は解釈されたものである。

### 3.5 「状態か過程か」は理論的には新しくない
- Tversky et al. 2002（表現形式と概念の一致）がこの交互作用を予測する。目標は状態に対する述語で、前提条件の失敗は遷移に属する。
- 学習研究では、アニメーションの優位は小さい（Höffler & Leutner 2007、d≈0.37。検索結果の抜粋での確認）。
- いずれも学習の研究であり、エージェントの計画の検証ではない。先行しているのではなく、事前の見込みを与える。**効果は小さいと見込むべきで、dz≈0.5は楽観的**（懐疑派）。
- PerceptTwinやSHRIMPの再生も最終フレームを含む。操作している要因は、正確には「静止・並置・提示時間を統制した表示」対「再生の中に埋め込まれた表示」である。

### 3.6 実装との差
各エージェントが `SYSTEM_OVERVIEW.md` を読んだ範囲での指摘（Unityのコードは未確認）:
- 現在のAR表示は、物体から目的地への弧とゴーストロボットの再生。これは論文が対抗する「過程の表示」にあたる。
- After状態の描画、Beforeとの切り替え、達成度の要約、ヘッドセット内の原因表示と修正は記載がない。
- Fetchは運動学シミュレーションで、MoveItは疑似実行。論文に明記する必要がある。
- サーバーは物体ごとの結果と、保留された手順の理由をすでに記録している（査読者の確認）。副作用の報告は記載がない。

## 4. 何を調べると新規性につながるか（優先順）

### 最優先: 読む
1. **MARCERとX-OOHRIを通読する。** どちらかに、ロボットが予測したシーン全体の結果表示があれば、インタラクションの主張は成り立たない。MARCERは最終状態の描画方法を図で確認する。
2. Diehl 2020（AR対RVizの誤り検出、N=18）の結果、PerceptTwinの条件別の正答率（検出力の計画に必要）。
3. 状態と過程の表示に関する可視化研究（Gleicher 2011、Robertson 2008は記憶に基づく引用で未確認）、FORTNIoTの実験設計。

### 作る
4. ヘッドセット内のAfter表示（Before切り替え、動く物体の強調）。
5. 最終状態で終わるゴースト再生。情報量をAfter表示と揃える。
6. 依頼スコープの印（中立、判定なし）。
7. 欠陥を仕込んだ計画のセット。LLMフロントエンドの実際の誤解釈を集めて決定的に再生する。

### 測る: 最初の実験（実証派の最終案、査読者と理論派の修正込み）

| 項目 | 内容 |
|---|---|
| 仮説 | After状態＋差分は、目標達成の欠陥に対するd′を過程の再生より高める。実行可能性の欠陥では優位がない（または劣る） |
| 設計 | 参加者内、すべてHMD、ロボットは静止、依頼文は常に表示 |
| 条件 | 過程（最終状態で終わるゴースト再生） / 状態＋差分（After、Before切り替え、動く物体を強調） |
| 共通 | 両条件に依頼スコープの印。判定は示さない |
| 試行 | 条件あたり40計画、うち20に欠陥 |
| 欠陥 | 解釈4、実行可能性4、欠落4、余計な変更4、副作用2、途中だけの違反2 |
| 統制 | 同じ計画を参加者間で両条件に回す（項目を変量効果に）。順序はラテン方格 |
| 回答 | 達成の度合い → 問題の物体の特定 → 確信度 |
| 段階 | 5秒提示（一目）→ 無制限 |
| 指標 | d′、判断基準、正しい判断までの時間、特定の正確性、確信度の較正、NASA-TLX |
| 分析 | 試行レベルの混合モデル。同等性検定を事前登録 |
| 人数 | N=48（dz≈0.5を想定。懐疑派は楽観的と指摘） |

どの結果でも報告できる:
- **状態が目標達成の欠陥でだけ勝つ**: 表示は欠陥の種類に合わせる必要があるという初の証拠。PerceptTwinの「効果なし」を説明する。
- **差がない**: 目標達成の誤りは表示の問題ではなく、ユーザーの意図が外に示されていないという問題。解釈された目標を見せる設計に向かう。
- **状態が負ける**: スナップショットは過程の欠陥を隠し、承認に傾かせる。「一目で理解」は、過程を強制的に見せる仕組みなしでは危険。

### 追加の実験（余力があれば）
- **判定の印あり条件**: 印の一部をわざと誤らせ、印が見逃す欠陥で判断基準がどう動くか（過信）を測る。
- **引き出すか、押し出すか**: 途中だけの違反、スコープ外の変更、時間・経路の規範で、過程の詳細をシステム側から出す条件と、ユーザーが求めたときだけ出す条件を比べる。
- **2D版の追試**: 同じシーングラフから描画した2D表示を、参加者間の追試として加える。AR優位の主張にはしない。
- **修正の実験**: ルールに結び付けた原因表示の有無。指標は修正成功率、時間、不要な修正の数（CE-MRS）、原因特定のF1（Das 2021）。
- **規模とDR**: 動く物体の数（約3 / 8 / 15）と、DRの有無による見逃し。

## 5. 残った対立点

| 論点 | 立場 |
|---|---|
| 想定する効果量 | 実証派はdz≈0.5、懐疑派は学習研究から見て小さい（d≈0.37程度）と見る。N=48で足りるかは未決 |
| システムは貢献か | 推進派は「実験に必要な、存在しない装置」として貢献を主張。懐疑派と査読者は装置にとどまると見る |
| ルールに結び付けた修正 | 推進派は「能力制約は編集できないが、ルールは編集できる」として差分を主張。懐疑派は内容の入れ替えと見る |
| 設計空間の空白 | 理論派の表はMARCERを含めて再コード化が必要。残る空白は「状態のみ＋不一致の印＋原因リンク」 |

## 6. 最大のリスク

- **効果が出ない。** 目標達成の誤りは、知覚ではなくユーザーが口にしていない好みに左右される可能性がある（Sukkerd 2020: 好みに合わない計画で正答のオッズが約0.36倍）。その場合、標語「一目で理解」は支持されず、貢献は検出力のある否定的結果になる。問い主導の論文なら残るが、システム主導の論文は残らない。
- **避けるべき主張**: 「初の〜」、「ARが優れている」、「LLM搭載ロボット」、「説明が理解を改善する」（CE-MRSとVizXPで理解と修正は乖離）、「家庭への展開」。
