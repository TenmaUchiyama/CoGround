## 2. 最も強い反例3件

1. **Tan, Brawer & Scassellati, "That's Mine!" (AAAI 2019)** — 主張A・B
   - 叱責1回から規範と所有の主張を同時に学び、色・位置・接触時間から所有者を推定した別の赤い物体に適用し、片付けをやり遂げる（場面1、図1上）。
   - 後で別のユーザーの命令を拒否する（場面2）。ただし場面2で変わるのはルールではなく、所有者という事実。
   - 限界: 禁止のみ（義務なし）、確率の閾値で行動するので「未確定」がない、言語理解と物体認識の方法は記述なし、家庭間の比較なし。
2. **RuleGraph (Taheri et al., arXiv 2610.24603, 2026)** — 主張Dの実行側
   - 指示のうち有害な部分を拒否し、残りを完遂する（TSR 84.54%、ASR 0%、表1）。ルールごとの検証をやめると TSR が10.3ポイント下がる（表4）。
   - 限界: ルールは設計者の一般安全原則、世界状態は記号のJSON（不明な値なし）、実機なし、家庭間でのルール入れ替えなし。
3. **AgentSpec (Wang et al., ICSE '26) と Wu et al. (arXiv 2611.18026)** — 主張B・Cの表現
   - AgentSpec: ルールをトリガー・属性チェック（`is_fragile_object` など）・強制に分け、タスクをまたいで持続させる。LLMが文章からルールを生成でき（強制95.56%、再現率70.96%）、ユーザーが確認する想定も書かれている。原文ルールとの比較はない。`stop` は依頼全体を止める。
   - Wu: 93個の安全ルールから、未見の場面とタスクに合わせてルールを選び計画を検査する。ルールの出所は記述なし、選択は依頼全体の単位、一部だけの実行なし、比較実験なし。

次点: SafeGate（不足事実で依頼全体を保留して質問）、VFM（NeurIPS 2026、ルールごとに満たす／違反／適用外）、Safety Chip（形式化した制約 > 自然言語の制約、ただし矛盾時はタスク全体を中止）、Jain 2013、FLEX（CoRL 2026）。

## 4. 議論で決着したこと

### 4.1 物体ごとの保留は、既存手法と振る舞いが違うか
推進派が実装（`norms/evaluate.py`）で次の2つを実行して確かめた。

- **偽のスコープが、欠けた属性を覆い隠す**: 「★の付いた物に18〜22時は触るな」で、★かどうか不明なカップの場合
  - 10時は「適用外」になり、片付ける。
  - 20時は「未確定」になり、不足事実として「★の有無」を返す。
  - 「不明なら常に保留」する方式は10時にも保留し、「不明は偽」と扱う方式は20時にも触る。
- **依頼者に結び付いた例外**: 「aliceが頼んだとき以外は★に触るな」の場合
  - aliceなら適用外、bobなら違反、依頼者不明なら未確定（不足事実は「依頼者」だけ）。
  - 別にある「割れ物に触るな」の判定は影響を受けない。

「1つの物体だけ保留して残りを進める」ケースはコードを読んだだけで、通しの実行はしていない。

Codexが示した**決定的なテスト**: 物体A（印が不明）、B（許可と分かっている）、C（禁止と分かっている）で、①返答を待たずにBを完了、②Cに触れない、③Aの印についてだけ質問、④許可の返答でAだけ再開、⑤スコープ外ならAは質問せずに進む。1物体を1単位にしたRuleGraph（事実・意味論・実行権限を揃える）がこれを再現できれば、この差分は消える。

### 4.2 星印・丸印テストは、そのままだと文字列一致になる
懐疑派の指摘を全員が認めた。属性の正解として `mark=star` を与え、ルールが★を名指すなら、どの方式も天井に達する。課題を意味のあるものにするには、次のいずれかが必要。
- 印を画像から認識させる（小さい、回転、隠れ）。
- ルール文を言い換える（「小さな星の付いたカップ」）、または間接参照にする（「おばあちゃんのカップ」を別に★と教える）。
- スコープ・例外・欠けた事実と組み合わせる。
- 紛らわしい印（アスタリスク、星柄の物体）や、複数のルールを混ぜる。

正解属性の条件は、性能の上限としてだけ使う。

### 4.3 分解の効果の仮説
先行証拠が割れているので、**両側検定で事前登録**する。
- RuleBench（質問応答）: 自然言語のルールが形式論理より良い場合が多く、反事実的なルールで大きく下がる。
- ShieldAgent: 行為ごとのルール回路が、ポリシー全文より+10.2%。
- Safety Chip 表I（懐疑派が全文で確認）: 自然言語のままの制約の安全率は54〜62%、形式化は84/94%、専門家の検証つきで100%。38%は制約なしの条件の値で、「38〜56%」という記述は誤り。

推進派の案: 単純なルールでは分解と原文の差は±5ポイント以内。★/●にスコープ・例外・欠けた事実が加わるほど差が広がる（方式×ルールの種類×要因の数の交互作用）。

### 4.4 公平性
- 全方式に、同じ出力形式（実行／残す／保留＋不足事実）、同じ候補リスト、同じ質問の予算を与える。
- ルールの検索と適用判定は分けて採点する。
- 物体には不透明なIDを使い、毎回新しいセッションにする（物体名から答えが漏れるのを防ぐ）。
- 既定の動作が走る前に、物体×行為ごとに適用判定を採点する（既定の動作がたまたま正しいと、照合の誤りが隠れるため）。

### 4.5 確認済みの事実
- PARSEC: 物体の組は「サンプリング」され、ユーザー間で同じとは書かれていない。配置のみ。反証にならない。
- RoboGuard 付録D-B: ルールの組ごとに環境とタスクも違う。同じ環境での入れ替えはない。
- Tan 2019 の著者: Zhi-Xuan Tan, Jake Brawer, Brian Scassellati（AAAI 33(01):8058–8065）。

## 5. 何を作り、何を測ると新規性になるか（優先順）

### 作る
1. **実際の属性認識**（VLM/OCRの `AttributeProvider`）。現在は正解属性だけなので、認識の誤りと照合の誤りを分けて測れない。
2. **比較方式の実装**（2〜3週間の見込み、査読者）:
   - 表現の比較（同じ実行器）: A1 ルール全文、A2 検索した原文、A3 AgentSpec/ShieldAgent型、A4 CoGroundの R。A3・A4は、人手で検証した変換とLLMによる変換の両方。
   - 保留の比較: B0 ルールなし、B1 1物体を1単位にしたRuleGraph、B2 依頼全体の保留、B3 未確定を許さない二値判定。
3. **場面生成器**と、ルールの `mark` 属性・対象述語。

### 測る（査読者の最終案）

| 項目 | 内容 |
|---|---|
| ルール | ★⇄○を交差させた5組（家庭Aで禁止の物体が家庭Bでは許可）＋「割れ物」の対照。印は材質・危険性・位置・置きやすさと釣り合わせる |
| 場面 | 24場面、1場面8〜12物体、紛らわしい印を2個以上。ルール文は字義どおり／言い換え／間接参照 |
| 分割 | 個体、カテゴリ、教えていない「対象×条件×行為」の組み合わせ（スコープが当てはまる場合と当てはまらない場合の両方） |
| 条件 | 画像から認識した印（主）、正解属性（上限）、属性の25%を隠す |
| 試行 | シミュレーションで方式・条件ごとに240組×3シード。実機144試行（2組×6場面×2家庭×2方式×3回） |
| 主要指標 | **対の成功**: 2つの家庭の両方で、禁止の物体に一度も触れず、許可の物体をすべて正しく片づけた割合 |
| 副次指標 | 禁止違反率、許可の完遂率、物体×行為ごとの適用判定の適合率・再現率、誤実行率、誤保留率、質問の精度 |
| 分析 | 場面でクラスタ化した一般化線形混合モデル。全方式が95%以上になる分割は除外することを事前登録 |
| 主要な比較 | A4対A2、A4対A3の2つだけ（α=.025ずつ） |

結果ごとの報告:
- **分解が勝つ**: 効果が出た分割を明記した、限定的な手法の主張。
- **差がない**: 主張Cを撤回し、ベンチマークと「任意のルールでは原文のLLMと分解が同等」という知見を報告する。方式×ルールの種類の交互作用は、それでも新しい。
- **分解が負ける**: 変換・認識・照合の誤りの内訳を示す否定的結果。

## 6. 論文に書ける貢献文と撤回条件

**貢献文（結果を前提にしない形）**

> 同じ場面と同じ包括的な依頼のまま、常識と相関しない住人のルールだけを家庭ごとに入れ替える対の評価プロトコルを定め、教えていない物体とルールの組み合わせについて、ルールの表現と物体ごとの未確定の扱いが、禁止の回避と許可の完遂を同時に満たす成功率、誤実行率、誤保留率をどう変えるかを測定する。

**撤回すべき条件**
- 場面と指示を固定し、住人のルールを入れ替えて物体ごとに両方を採点した先行研究が確認された（まずPARSECとNormActの付録を確認する）。→ 評価の新規性を撤回し、残るのは手法の主張だけ。
- 1物体を1単位にしたRuleGraph（事実・意味論・権限を揃えたもの）が、4.1の決定的なテストを再現した。→ 未確定の扱いの独自性を撤回。
- 未確定の扱いが、誤実行を減らした分だけ誤保留を増やしただけだった。→ 未確定の扱いの利点を撤回。
- 画像認識と言い換えを入れても、星印・丸印の条件で全方式が天井に達した。→ ベンチマークとして無意味。
- 方向のある主張（分解が勝つなど）が、事前登録した最小の差に届かない、または原文方式・AgentSpec型の信頼区間に入る。→ その主張を撤回。
- 効果が正解属性だけ、人手で検証した変換だけ、または「割れ物」ルールだけで出た。→ 主張をその条件に限定する。

**推奨する発表先**: ICRA / IROS / RA-L（評価として）。HRI / RO-MANなら、教える負担のユーザー実験を加える。CoRLは、画像認識の条件で分解が勝った場合のみ。
